# Clash of Valor 2D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the `ascii3d/` glyph duel into a separate 2D pixel-art game: three-quarter battle view at 480x270, fighters as cut-out part sprites driven by the existing pose rig, all art built by Claude and approved by the user class by class.

**Architecture:** Duel logic (`rules`, `bot`, `flow`, `anim`) and the effect simulation (`effects::Fx`) stay. A fixed affine **stage map** turns world points into 480x270 screen points; each fighter's skeleton is drawn through its own cheated front-3/4 **figure view** (fighter 1 mirrored), parts are chained in 2D with their drawn lengths (never stretched), and effect anchors are written back so effects land on the drawn weapon. Art is authored as text pixel maps (`art/`) and compiled to committed PNGs (`assets/`) by a small tool, `artc`.

**Tech Stack:** Rust 2024, macroquad 0.4 (render target + nearest-neighbour textures), `png` crate (artc only). Existing `rayon` dependency is removed with the ray marcher.

**Spec:** `docs/superpowers/specs/2026-11-25-pixel-art-2d-design.md`

## Global Constraints

- Work only in worktree `~/DEV/ClashOfValor-pixel-spike`, branch `pixel-spike`. Never touch `~/DEV/ClashOfValor` or branch `ascii-3d`.
- Do not change the logic of `rules.rs`, `bot.rs`, `flow.rs`. Their existing tests must keep passing unmodified.
- Internal resolution 480x270. One pixel size for everything; nearest-neighbour only; no bilinear filtering anywhere (`FilterMode::Nearest` on every texture and on the render target).
- Sprites never stretch. Part rotation is allowed; scaling a part is not.
- Keep flags `--shot`, `--duel`, `--moves`, `--at`, `--ff`, `--keys`, `--size`, `--metal`. Remove `--yaw`, `--dist`, `--noedges`, `--pixel`.
- Runtime reads only `assets/`. `artc` and `art/` are build-time only; generated PNGs are committed.
- New dependencies allowed: `png` only.
- Before running the game or `--shot` in a shell without display variables: `export XDG_RUNTIME_DIR=/run/user/$(id -u) WAYLAND_DISPLAY=wayland-1`.
- Commit messages end with the session's attribution lines.

## Review Focus

1. **Window sizes that are not a multiple of 480x270, or smaller than it.** Expect letterboxed integer scaling, and the "Make the window larger" message below 480x270, never a crash or a stretched image. Pinned in Task 2 (`fit_*` tests).
2. **The mirrored fighter (player 2 on the lower right).** Expect parts in the same order and rotation as the unmirrored fighter, with no part flipped the wrong way. Pinned in Task 5 (`mirrored_part_points_along_bone`).
3. **Collapse and fall poses.** Expect the fighter lying on the ground with every part at its drawn length, and no NaN or part flying off. Pinned in Task 5 (`fallen_figure_stays_whole`).
4. **Long names and long log lines in the pixel font.** Expect clipping or wrapping inside panels, never overflowing the 480px frame. Pinned in Task 7 (`fit_respects_pixel_width`).
5. **Broken or hand-edited art files.** A malformed `.px` file should produce a `file:line` error, and a PNG the user edited by hand should not be overwritten. Expect no panics and no silent loss. Pinned in Task 4 (`parse_*_errors`, `should_write_*`).

- **Palette file:** one entry per line, `<char> #rrggbb <name>`; `.` is always transparent; `#` lines are comments. Reserved key entries with exact names `metal1`..`metal4` (light→dark) and `accent1`..`accent3`; their colours are placeholders swapped at runtime (Task 6).
- **Pixel map file (`.px`):** header lines `part <name>`, `bone <JointFrom> <JointTo>` (names from `Joint::name`), `pivot <x> <y>`, `end <x> <y>`, `layer <n>`, then a line `grid`, then rows of palette chars, all the same width. Errors are `"<file>:<line>: <message>"`; messages include `unknown palette char 'Q'`, `row has width 5, expected 6`, `missing pivot` (likewise for each header).
- **`artc` CLI:** `cargo run --bin artc -- [--force]`. Reads `art/palette.txt` and every `art/fighters/<class>/*.px`; writes `assets/fighters/<class>/<part>.png` and `assets/fighters/<class>/parts.txt` (one `format_part_line` per part, sorted by name), copies the palette to `assets/palette.txt`, records `<path> <fnv64 hex>` per written PNG in `assets/manifest.txt`. A PNG whose current hash differs from the manifest is skipped with `hand-edited, not overwriting: <path>` unless `--force`. Parse errors print and exit 1. Later tasks add backdrop, font and effect outputs to the same tool.
- `parts.txt` line format: `<name> <from> <to> <px> <py> <ex> <ey> <layer>`, whitespace-separated.

### Task 5: Figure solve: no-stretch part chaining and anchor write-back (`src/figure.rs`)

**Files:**
- Create: `src/figure.rs`

**Interfaces:**
- Consumes: `stage::{to_screen, from_screen, figure_point, depth}`, `Body::posed`, `Body::to_local`, `models::{Joint, Skeleton, Anchors}`, `pixmap::PartLine`.
- Produces:
  ```rust
  pub struct PartDef { pub name: String, pub from: Joint, pub to: Joint,
                       pub pivot: Vec2, pub end: Vec2, pub layer: i32, pub size: Vec2 }
  impl PartDef { pub fn from_line(l: &PartLine, size: Vec2) -> Option<PartDef>; pub fn len(&self) -> f32; }
  pub struct Placed { pub part: usize, pub pos: Vec2, pub angle: f32, pub layer: i32, pub depth: f32, pub mirrored: bool }
  pub struct Figure { pub placed: Vec<Placed>, pub joints: [Vec2; Joint::COUNT] }
  pub fn solve(who: usize, body: &Body, sk: &Skeleton, parts: &[PartDef]) -> Figure;
  pub fn corrected_anchors(body: &Body, sk: &Skeleton, fig: &Figure) -> Anchors;
  pub fn rotate(v: Vec2, angle: f32) -> Vec2; // y-down: (x cos - y sin, x sin + y cos)
  pub fn limbs_from_parts(parts: &[PartDef]) -> Limbs; // sprite length / 56 px per metre
  ```
- **Solve:** project every joint with `figure_point(who, to_screen(body.pos), body.posed(j))` → `raw`. Joints that no part ends at (`Hip`, `Neck`, shoulders, hips) keep `raw`. Parts are processed parent-first (a part whose `from` joint is another part's `to` waits for it). For each part: `start = joints[from]`; `dir = normalize(raw[to] - raw[from])`, falling back to the sprite's own direction when that length is under 0.5px; `joints[to] = start + dir * len`. Sprite vector `sv = end - pivot`, with x negated when `mirrored` (`who == 1`); `angle` is the rotation with `rotate(sv, angle)` parallel to `dir`. `pos = start` (the pivot's screen point). `depth = stage::depth(posed(midpoint of from/to))`. `placed` is sorted by `(layer, depth)`.
- **Anchor write-back:** for `weapon_tip` (`WeaponTip`), `hand_r` (`HandN`), `head` (`HeadTop`), `chest` (`Hip` + 0.6 × (`Neck` - `Hip`) in 2D) and `focus` (`WeaponTip` for Sorcerer, otherwise `chest`): take the 2D point `s`, the raw joint's world z `z = body.to_world(sk.get(j)).z`, and store `body.to_local(from_screen(s, z))`. Effects then land on the drawn point because `to_screen(body.to_world(anchor)) == s`.

- **Canvas:** `render_target(480, 270)` with `FilterMode::Nearest`; all world, fighter and effect drawing goes through a `Camera2D` mapped to 480x270. `present` draws the target at `fit.offset` scaled by `fit.scale`; when `fit.scale == 0`, draw `ui::draw_too_small` instead.
- **Backdrop:** `artc` generates `assets/backdrop/{sky,hills,trees,ground}.png` at 480x270 from the palette (banded Bayer-dithered sky with moon and stars, far hills, pine treeline, grass with the dirt clearing, as in the approved mockup), plus a 3-frame campfire sprite. The campfire is drawn at `to_screen(scene.fire)`. `parallax` maps the idle sway to offsets of 0, 1, 2 and 0 px peak for the four layers.
- **Palette slots:** `ramp` multipliers are exactly `[1.15, 1.0, 0.7, 0.45]` for metals (clamped to 1.0) and `[1.15, 1.0, 0.65]` for accents. Key colours `metal1..4` map to `ramp(METALS[metal].rgb, 4)`, `accent1..3` to `ramp(ACCENTS[i], 3)`. Recoloured textures are cached per `(class, metal, accent)`, built on first use.
- **Drawing a fighter:** each `Placed` drawn with `draw_texture_ex` at `pos.round()` with `pivot` = the part's pivot point, `rotation = angle`, `flip_x = mirrored`. Far parts (`from` joint name ends in `F`) are tinted `0.78`. Hit flash draws a white-silhouette copy of each part on top with alpha `flash`. `dim` sets alpha `1 - dim`. The fighter with the larger `ground_key` (lower on screen) draws last.
- **Main loop:** each frame: tick as today → for each body: `sk = skeleton(...)`, `fig = solve(...)`, `body.anchors = corrected_anchors(...)` (before `world.tick` uses them next frame) → canvas: backdrop, campfire, fighters and particles in `ground_key` order, shake offset (`world.shake.offset_in(Vec3::X, Vec3::Y)` × 56, rounded) applied to the whole canvas camera → present → old HUD on top in window space. Keys M/N stay, F3 shows fps only; mouse orbit, E, F, G and L are removed.
- **Effects (interim):** `effects::draw` takes the canvas and draws each particle as one pixel at `to_screen(p.p)` in its colour with alpha fade; the orb as a filled 3px circle; texts skipped until Task 7.
- **Shot:** `--shot path` captures the canvas after the same frame count as today, reads it back, `flip_rows` (fixes the upside-down export), `scale_nearest` by `--scale N` (default 4), writes PNG. No `magick` step needed afterward.
